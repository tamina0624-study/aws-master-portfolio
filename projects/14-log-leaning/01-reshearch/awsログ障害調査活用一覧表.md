# AWSログの障害調査活用一覧表

| ログ種別 | 主な障害調査・用途 |
|---|---|
| CloudTrail（API操作履歴） | 誰が・いつ・どのリソースに対して操作したかの追跡、不正操作や設定変更の調査 |
| CloudWatch Logs（アプリ・システム・カスタムログ） | アプリケーションやOSのエラー・例外・パフォーマンス問題の特定、詳細な動作ログの分析 |
| S3アクセスログ | S3バケットへのアクセス状況、不正アクセスやデータ流出の調査、アクセス元IPの特定 |
| VPC Flow Logs | ネットワーク通信の可否、セキュリティグループ/NACLの影響、通信断や遅延の原因特定 |
| ELBアクセスログ | ロードバランサー経由のリクエスト状況、エラー発生時のリクエスト内容やパターン分析 |
| RDS/Auroraログ | データベースのエラー・スロークエリ・接続問題の調査、SQL実行履歴の確認 |
| Lambdaログ | Lambda関数の実行状況、エラーやタイムアウト、入力イベントの内容確認 |
| API Gatewayアクセスログ・実行ログ | APIリクエスト/レスポンスの詳細、認証・認可エラーやスロットリングの調査 |
| VPCエンドポイントアクセスログ | プライベート接続経由の通信状況、アクセス元/先の特定、通信失敗の原因調査 |
| lambdaのデッドレターキュー | Lambda非同期実行失敗時のイベント内容、再処理や原因分析 |
| route53ログ | DNSクエリの内容、名前解決失敗や不審なアクセスの調査 |
| WAFのログ | 不正リクエストの検知、攻撃パターンや遮断状況の分析 |
| GuardDutyのログ | セキュリティ脅威の検知、アラート発生時の詳細調査 |
| ロードバランサーのログ | ELBアクセスログと同様、リクエスト状況やエラーの分析 |
| EC2のcloudwatch Agentのログ | サーバリソースのメトリクス・ログ、CPU/メモリ/ディスク異常やアプリ障害の調査 |
| その他各サービス固有のログ | サービスごとの障害・異常検知、詳細なトラブルシュート |

---

必要に応じて、具体的な障害例や調査手順も追記可能です。

## 障害を発生させる手順例

### 1. CloudTrail（API操作履歴）
- IAMユーザーで意図的にS3バケットやEC2インスタンスの設定変更を行う
- 不正なAPI操作（例：許可されていないリソース削除）を試行

### 2. CloudWatch Logs（アプリ・システム・カスタムログ）
- EC2上のアプリケーションでエラーを発生させる（例：存在しないファイルを参照）
- OSで意図的にサービスを停止し、エラーログを出力

### 3. S3アクセスログ
- S3バケットに対して外部からアクセス（許可/拒否両方）
- 不正なIAMユーザーでアクセスを試みる

### 4. VPC Flow Logs
- セキュリティグループやNACLで通信を拒否し、疎通不可状態を作る
- 存在しないIP宛に通信を試みる

### 5. ELBアクセスログ
- バックエンドのEC2を停止し、ELB経由でエラーを発生させる
- 不正なリクエスト（例：存在しないパス）を送信

### 6. RDS/Auroraログ
- 誤ったパスワードで接続を試みる
- 意図的にスロークエリを発生させる

### 7. Lambdaログ
- Lambda関数で例外を発生させる（例：ゼロ除算）
- タイムアウトを意図的に発生させる

### 8. API Gatewayアクセスログ・実行ログ
- 認証情報なしでAPIにアクセス
- レート制限を超えるリクエストを送信

### 9. VPCエンドポイントアクセスログ
- 許可されていないリソースへのアクセスを試みる

### 10. Lambdaのデッドレターキュー
- Lambda非同期実行で失敗するイベントを送信

### 11. Route53ログ
- 存在しないドメイン名で名前解決を試みる

### 12. WAFのログ
- WAFルールに該当する攻撃リクエストを送信（例：SQLインジェクション）

### 13. GuardDutyのログ
- テスト用の疑似攻撃（GuardDutyのサンプルイベント）を発生させる

### 14. ロードバランサーのログ
- ELBのバックエンドを停止し、エラーを発生させる

### 15. EC2のCloudWatch Agentのログ
- CPUやメモリを意図的に高負荷状態にする

### 16. その他各サービス固有のログ
- サービスごとに障害を発生させる操作を実施

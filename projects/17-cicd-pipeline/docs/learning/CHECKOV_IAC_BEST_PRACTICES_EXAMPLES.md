# Checkovで検出できるIaCベストプラクティス違反の具体例

## 概要
このドキュメントは、CheckovがTerraform構成から検出できる代表的なベストプラクティス違反をまとめたものです。

## 1. S3のパブリック公開
- 例: バケットポリシーやACLで全世界に読み取りを許可
- リスク: 機密データ漏えい
- 検出観点: Public Access Block未設定、公開ポリシー許可

## 2. S3暗号化未設定
- 例: バケットのサーバーサイド暗号化を有効化していない
- リスク: 保存データの平文保管
- 検出観点: SSE-S3またはSSE-KMS未設定

## 3. S3バージョニング未設定
- 例: 誤削除や上書き対策としてのバージョニングが無効
- リスク: 障害時の復旧困難
- 検出観点: versioning未有効

## 4. Security Groupの過剰開放
- 例: 22番や3389番を0.0.0.0/0に開放
- リスク: 不正アクセス、総当たり攻撃
- 検出観点: 危険ポートの無制限Inbound

## 5. IAMポリシーの過剰権限
- 例: ActionやResourceにワイルドカードを使用
- リスク: 権限昇格、被害拡大
- 検出観点: 最小権限原則違反

## 6. CloudTrailなど監査設定不足
- 例: API操作ログの収集が無効
- リスク: インシデント調査困難
- 検出観点: 監査ログ設定不足

## 7. RDSの暗号化・バックアップ不足
- 例: storage_encrypted無効、自動バックアップ無効
- リスク: データ漏えい、復旧不可
- 検出観点: 暗号化と可用性設定の不備

## 8. EBS暗号化未設定
- 例: ボリュームやスナップショットに暗号化なし
- リスク: ストレージ流出時の情報露出
- 検出観点: at-rest暗号化未設定

## 9. シークレットのハードコード
- 例: Terraform変数やlocalsに秘密情報を直接記述
- リスク: リポジトリ漏えい時の即時侵害
- 検出観点: シークレット管理ベストプラクティス違反

## 10. ネットワーク保護機能の不足
- 例: 保護対象にWAF等の防御設定がない
- リスク: 攻撃面の拡大
- 検出観点: 推奨セキュリティコントロール未適用

## 実務での優先対応順
1. 公開設定と過剰権限を最優先で修正
2. 暗号化設定を全面適用
3. 監査ログとバックアップを整備
4. 例外ルールは期限付きで管理し、恒久化を防止

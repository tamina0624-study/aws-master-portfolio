# ネットワーク監視・到達性分析 学習結果まとめ

## 1. 学習全体の目的

本学習では、AWS のネットワーク運用を以下の 2 軸で強化することを目的に整理した。

- 監視軸: ネットワーク全体の状態可視化と異常検知
- 分析軸: 通信可否の原因切り分けと設計段階での経路リスク検出

今回は Network Manager 系機能を中心に、以下の項目を確認した。

- Global Network によるトポロジーとステータスの確認
- AWS Transit Gateway Network Manager
	- Transit Gateway ルートアナライザー
- VPC Reachability Analyzer
- AWS Network Manager Infrastructure Performance
- AWS Network Access Analyzer

## 2. 各テーマの学習要点

### 2-1. Global Network

- Global Network 配下で TGW / VPN / 拠点接続を俯瞰し、接続状態を一元監視する考え方を学習
- パケットロス、スループットなどの指標を確認できることを確認
- 接続異常時に「どの区間で問題が起きているか」を把握し、一次切り分けを迅速化する運用イメージを整理

### 2-2. AWS Transit Gateway Network Manager

- ルートアナライザーを使うことで、Transit Gateway 間の経路や疎通性を確認できることを確認
- 本機能により、経路上のどこに問題があるかを把握できた

### 2-3. VPC Reachability Analyzer

- 送信元から宛先までの到達性をパス単位で分析し、通信断の遮断点を特定する手順を学習
- SG / NACL / ルート / Gateway といったレイヤー別に原因を切り分ける実践的な調査フローを整理
- 障害調査の標準手順として、現象確認から原因特定までの再現性を高められることを確認

### 2-4. AWS Network Access Analyzer

- AWS が提供するネットワーク分析手法を学んだ
- 本機能を利用することで、疎通可能なネットワークインターフェースを洗い出せることを確認
- 意図しないグローバルアクセスの穴を検出できることを学んだ

## 3. 実務適用イメージ

- 平常時
	- Network Manager で全体ヘルスと性能傾向を確認
	- しきい値超過やステータス変化を早期把握
- 変更前
	- Network Access Analyzer で意図しない経路を事前検出
	- 設計レビューで公開範囲と到達性を明確化
- 障害時
	- 以下の組み合わせによる調査が有効と考える
	- トポロジー表示でグローバル視点の問題箇所を特定
	- VPC Reachability Analyzer で、対象サービスから Gateway までの疎通性を確認
	- Transit Gateway ルートアナライザーで VPC 間の疎通性を確認

## 4. 学習成果（結論）

- ネットワーク運用は「全体監視」と「経路分析」を分けて使うことで精度と速度が上がる
- Network Manager 系は運用監視・全体把握に強く、Analyzer 系はレビュー・原因調査に強い

今回の実感として、以下を強く感じた。

- 便利なサービスではあるが、少し癖が強いため、一度は実際に触っておく価値がある
- 環境構築時に AI 設計の粒度が粗いと、非効率な構築作業が発生しやすい
- AI 活用を安定させるには、事前に使うフレームワークや進め方の型を持つことが重要
- AI 活用手法を知らないと、自力でコードを書く必要がある場面が増える可能性がある
- 作業効率を高めるために、再利用可能なフレームワークを継続的に蓄積する必要がある
